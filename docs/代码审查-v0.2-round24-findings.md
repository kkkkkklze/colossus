## 一、指纹闸（resumeFrom / digestOf / 位图越界）

三个边界点先按字面算清楚（Java 的 `<<` 取模 64，判据是 `state/FrameRunner.java:220`
`if (n < MAX_PERSISTABLE_FRAMES && (bitmap & (-1L << n)) != 0L)`）：

- `n=0`（空帧表）：`-1L << 0 == -1L` ⇒ 任何非零位图都被拒。语义正确——空表没有任何位属于它。
- `n=63`：`-1L << 63 == 0x8000…0000` ⇒ 只查第 63 位。正确（0..62 合法）。
- `n=64`：前置 `n < 64` 为假 ⇒ **整条判据让路**，满宽度位图 `-1L` 被放行（`StateSelfTest.java:558` 钉了
  `fullTableAcceptsAllBits`）。这正是要躲开 `-1L << 64` 别名回 `<< 0` 的那一手，两头都钉住了。✓

`digestOf`（`:252-260`）与实例字段 `framesDigest`（`:73/:79`）不一致的风险**不存在**：
`frames` 是 `List.copyOf(...)`（`:128`）且 `Frame` 是 record（`:50`），建完之后没有任何写路径，
所以"builder 之后帧表可变"这一类在这里被不可变性挡死。`MoveDef.framesDigest()`（`move/MoveDef.java:113`）
走的是同一个静态 `digestOf`，`MoveDef.of` 也做了 `List.copyOf`（`:105`）⇒ 两侧同调。✓
"该拒的没拒"只剩理论上的 FNV-1a 碰撞，不是本轮要开的单。

### A-2（P3）`tickAt` 半侧没有域闸门，与位图半侧不对称

`classifySeal/worldReady` 两个布尔判据，没有任何"这条账属不属于这个世界"的合法域。

### D-3（P3）`Spec` 的"合法域只有一个地方定义"只覆盖四个数值参数，`sealBlock`/`sealOffsets` 一格都没查
