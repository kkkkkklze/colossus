## P0 死亡管线死循环 —— ✅ 已修
`resolveDeath` 复位 `deathPending=false` 后 `this.die(source)` 二次进入挂起分支，`super.die` 永不执行；叠加 `StateController.tick` 在 `onTick` 内被 `forcePush` 换栈时外层 pop 掉新状态——净结果：击杀后 Boss 变**无敌 1 血雕像、永不移除、loot 缓冲丢失**。

# 审查轮 10（第二十批 not_recent 专查：空窗算式 / 降权语义 / 环的三条核心判据）处置记录

轮 10 交回一条**结构性设计缺陷**，而且带的算式我逐条复算过、全部成立：

**F1 `not_recent` 造成的空窗不随等待消解，挂满窗口就是永久死锁。**
环形历史只由"又出一次招"推进，而选招是每 tick 重试——所以"等一会儿就好了"在这里不成立。
我按源码规则重放确认了三件事：`ColossusBossEntity#trySelectAttack` 对 `pick` 返回 empty **没有任何分支**
（无保底、`BossApproachGoal` 只移动不打）；示范表在"阶段 0 + 贴脸"下最坏空窗 **70t（3.5s）**，
出厂 demo 数据包合进表之后在"目标 8 格外"是 **140t（7s）**（无历史门时分别是 40t / 90t）；
而"表内每条招都挂 `not_recent(w)` 且 `w >= 可用招数`"是**真死锁**（`PhaseChangeState` 的
`resetAttacks` 只清冷却不清历史，救不了）。

**修法不是"兜个底"就完事，而是让引擎看得见这道门**：`notRecent` 从 `extraCheck` 里的一个
lambda 升成 `MoveDef` 的数据字段（DSL `.notRecent(n)` / JSON `requires.not_recent` 都写它），
`MoveSet.pick` 于是能分两遍——第一遍全门都算，**整表被历史挡空时只放开历史门再选一次**；
阶段/距离/自定义谓词/冷却/权重≤0 照样硬拒（保底不会把没解锁的招放出来，这条有反向断言钉）。
窗口值域同时钉在登记期：DSL setter 抛带招式名的 IAE、JSON 给字段级回执、`MoveDef` 构造器兜底；
`MoveSet` 构造时若"每张招都挂 `notRecent >= 表长`"打一条 warn 说破作者其实想要轮换
（本批跑桩时这条 warn 真的响了 1 次，不是装饰）。

**F2 `recent_band` 原先不是"降权仍可选"，是换个入口禁选**：demo 表自己的
`base 3 + distance_band(0) + recent_band(-6) = -3`，在 >6 格时被 `pick` 的 `w<=0` 整条丢掉——
我上一批文档里写的"用过就降权，仍可被选中"当场不成立。修法是把普通项与历史项分开攒：
普通项之和若非正，那是作者真的要禁用（保留原语义）；历史项只能在正数基础上往下压，
**地板是 1**。GameTest 加了一条正向覆盖：放过 quake 之后，在 8 格外的定种子第 2 掷必须仍选得到它（老写法它是 -3 整个出局，一次都不会中）。【轮 12 收回：那条判据后来被证明只有 1 个 bit（每轮新建同种子 RandomSource），第二十二批改成直接断权重、第二十三批再改成精确值 1；原文留着不删。】

**F3 同一个窗口值两侧不对称**：JSON 侧越界拒、DSL 运行期 `ctx.usedRecently(20)` 静默钳到 8。
这条**不强行统一**：运行期在每 tick 的选招路径上抛异常，等于把数据错误炸进战斗（轮 9 刚为
DSL 登记期抛 IAE 踩过崩溃循环）。处理是**把不对称写进 javadoc** 并指回一等入口
