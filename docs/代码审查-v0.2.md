## P0 死亡管线死循环 —— ✅ 已修
`resolveDeath` 复位 `deathPending=false` 后 `this.die(source)` 二次进入挂起分支，`super.die` 永不执行；叠加 `StateController.tick` 在 `onTick` 内被 `forcePush` 换栈时外层 pop 掉新状态——净结果：击杀后 Boss 变**无敌 1 血雕像、永不移除、loot 缓冲丢失**。
修法：`resolveDeath` 直接 `super.die(source)`（不再走 `this.die`），`deathPending` 保持 true 让死亡序列期间继续免伤。
**为什么编译/自检没抓到**：StateSelfTest 用 `List<String>` mock 驱动状态机，从不调 `die/resolveDeath/DeathState`——"唯一必须跑通的击杀路径"恰好零覆盖。**教训**：mock 主循环的自检验不了与 MC 生命周期交互的分支。

## P1 死亡期血条不隐藏且被回填 —— ✅ 已修
`setProgress(barProgress())` 在 deathPending 早退之前跑，`onDeathSequenceStart` 设 0 下一 tick 被覆回 1/max。修：常规回填加 `!deathPending` 门 + 演出开场 `setVisible(false)`。

## P1 演出中区块卸载 → 1 血复活 —— ✅ 已修（续演路径）

# 审查轮 5（第八/九/十批回归专查，2026-09-24）处置记录

审查代理对 1.20.1 sources jar 核了 16 条 API 事实（`Mob:742` serverAiStep final、`customServerAiStep` 挂点顺序在 `moveControl.tick()` 之前、`CompoundTag.putUUID/getUUID` 在 `:191/195/199`、`ServerPlayer:1199` 末两参是 (yaw,pitch) 且挂 `POST_TELEPORT`、`Entity.discard()=remove(DISCARDED)` 不经 `die()`、`LivingEntity:1305` 的 die 幂等门 ⇒ 转发无环也无二次结算）。**三条 P1 我逐条回读自己的代码复核，全部成立**，无一条误报。

**P1-1 读档后成员全部贴到队长原点**：锚点走"补员时注入字段"，而字段不入 NBT，重载后 `findMember` 按 UUID 命中即 `continue`，注入永不重做 → `anchorOffset()` 回落 `ZERO`；血条/伤害转发照常，纯位置错乱（最难查的一类）。修法**删掉注入路径**：`anchorOffset()` 每次现查 `leader.squad().defFor(memberKey()).localOffset()`——定义表才是锚点的唯一来源，`setAnchorFromDefinition` 与 `SquadManager` 里的注入调用一并删除（不留新旧两条路）。
**P1-2 越界纠偏不看维度**：`participants()` 是全服名单，跨维玩家的坐标与本维 AABB 恒不相含 → `teleportTo(level,…)` 落进 `ServerPlayer:1435` 的**换维通道**（`ClientboundRespawnPacket` + 过 `onTravelToDimension`），等于把正在下界的人硬拽进封闭竞技场，还是在别人实体 tick 内发起换维。修法：`if (p.level() != level) continue;`。
**P1-3 宽限期"销账不销人"+ 销账不核 UUID**：账位被新 UUID 顶替后，旧那具重新加载就是**同 key 两具**（血条只算账内那具、收摊广播漏掉孤儿）；而 `onMemberDefeated(key)` 按 key 盲销，会把现役成员从账上抹掉。修法：`onMemberDefeated(key, memberId)` 只在账上就是它时才销；成员侧加**孤儿回收**（`customServerAiStep` 里 `squad.defFor(key)!=null && !squad.isCurrent(key,uuid)` → `discard()`，只对有定义的 key 动手，外部自挂成员不受此门管辖）。

**P2-4 团灭复位挂在易失名单上**：团灭后玩家在死亡界面退服 → 名单空 → `hasTracked()` 恒 false → `fail()` 不触发 → 深板岩封路**永久留在世界**。修法：`everEngaged` 入会话 NBT，判据改「曾有过真人 ∧ 活着的人为空」；`begin()` 不设该位（否则 GameTest 的 mock 玩家会立刻判成团灭），只在 `trackedIncludingFallen` 非真空中置位。顺手：`outOfBoundsGrace/warnCooldown` 按在册名单 `retainAll`（下线残项）、`EngagementTracker.hasTracked` 删除（死代码）并在 `isEmpty` 上写明"别拿它判团灭"。
**P2-5 测试有效性**：`squadLedger` 最后一条"等 140t 数实体"是**恒真断言**（那时 Boss 已 `isRemoved`，`squad.tick` 整体停摆，删掉 `leaderDown` 门也照样绿）。改成 `boss.squad().respawnPending() == 0`——队列有值即门被拆，判别力真实。同时如实记录：越界拉回与 `fail()` 两条分支**仍无真机覆盖**（mock 玩家进不了 `server.getPlayerList()`），列入 v0.3 的场景化测试桩。

**P3 已修 6 条**：`spawnMissing` 在 `type.create` 返回 null 时不再先销账（否则下一 tick 绕开宽限期立刻刷）；`applySeal` 解封改为**只认快照位**（原按解封时刻朝向重算偏移，Boss 打过架必然对不上账，全靠兜底救——删掉 `unsealOffsets` 这条误导性字段）；封位被占时 `LOGGER.warn`（原来静默留缺口）；`safeLanding` 加 `hasChunkAt` 门（服务端 `getBlockState` 会强制生成区块）；`arena()` 每 tick 新建 Spec 的分配改为**探针缓存**；成员基类注释与 `Spec` javadoc 同步。
