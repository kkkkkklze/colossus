## 1. `gameTestAudit` 现在是个不会响的铃

- 本工程的 `gameTestAudit` 用 `startsWith('@GameTest(')` 数条数 —— **裸写 `@GameTest`（不带括号）的那一条数不到**，
  于是"声明了多少条测试"这个分母本身是错的。
- 它**没有接进 `check`**（`check` 的依赖里看不到它）。结果：平时 `./gradlew build` 不跑它，
  测试条数掉到 0 也不会有人知道。
- 建议：数法换成按行正则匹配 `^\s*@GameTest`（主工程 `forge-1.20.1-mod-2/build.gradle` 的
  `gameTestAudit` 就是这个形状，可整段抄），并把任务接进 `check` 的依赖里；
  同时把"下限"从硬编码小数字改成**当前真实条数**（低于它就红），不要留 2 这种摆设。

## 2. `runGameTestServer` 退出码 0 ≠ 真的跑过（今天在主工程实测到）

现象：gradle 报成功，日志里 GameTest 服务器**启动即抛**
`java.io.IOException: 另一个程序已锁定文件的一部分`（`run/logs/latest.log` 被上一个残留 JVM 占着，
log4j 删不掉旧日志就崩），一条测试都没执行。

建议本工程加一道结果标记（主工程对自证/压力门用的 `verify*Result` 就是同一个套路，可抄）：
GameTest 跑完由测试自己往 `build/gametest-result.txt` 写一行带条数的记录，
另一个任务校验"文件存在 + 条数 ≥ 下限"，并在跑之前删掉旧标记——否则"上一次的 PASS"会冒充这一次的。
